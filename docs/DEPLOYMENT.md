# Hosting nach dem lokalen Prototyp

Es wurde kein Deployment durchgeführt und kein kostenpflichtiger Dienst angelegt. Für die nächste Abnahme ist der lokale Server plus privater Secure MCP Tunnel der vorbereitete Weg; Details in [CHATGPT.md](CHATGPT.md).

| Weg                                              | Passung zum aktuellen Code                                                                                                            | Persistenz / Laufzeit                                                                                                                                       | Kostenbetrachtung                                                                                     |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Lokaler Node-Prozess + Secure MCP Tunnel         | Unveränderter Streamable-HTTP-Server, private Verbindung                                                                              | JSON bleibt lokal, Rechner und Tunnel-Client müssen laufen                                                                                                  | Lokale App ohne Dienstgebühren; Tunnel-/Kontobedingungen gesondert prüfen                             |
| Google Cloud Run                                 | Node-Container eignet sich für Express und den aktuellen SDK-Transport; `HOST=0.0.0.0`, `PORT` aus Umgebung, Servicehostname erlauben | Instanzen skalieren/enden; lokale Dateien sind flüchtig. Für gemeinsame dauerhafte Speicherung Adapter ersetzen; stateless MCP vermeidet Session-Affinität  | Nutzungsabhängige Abrechnung und Kontobedingungen; mögliche Freikontingente sind keine Kostengarantie |
| Cloudflare Workers                               | Erfordert Anpassung an die Worker-Fetch-Laufzeit und einen passenden Web-Standard-Transport                                           | Node-Kompatibilitätsflags ersetzen keine dauerhafte JSON-Datei. z. B. D1/Durable Objects mit transaktionaler Idempotenz prüfen; CPU-/Requestlimits beachten | Free-/Paid-Grenzen vor Entscheidung anhand aktueller Tarife prüfen                                    |
| Kleine VM / Node-Hosting mit persistentem Volume | Geringste Codeanpassung, ein Prozess mit eigener JSON-Datei möglich                                                                   | Backups, TLS, Prozessüberwachung und Authentifizierung selbst betreiben                                                                                     | Dauerhafte Instanz kann laufende Gebühren verursachen                                                 |

**Bewertung:** Für eine spätere Container-Testinstallation ist Cloud Run nahe am vorhandenen Node-Code. Für Workers sind Transport- und Storage-Anpassungen erforderlich; die UI und reinen Berechnungen bleiben wiederverwendbar. Für echte Nutzerdaten zuerst Authentifizierung, Autorisierung und einen für mehrere Instanzen geeigneten Adapter entwickeln. Der aktuelle JSON-Adapter darf nicht zwischen Cloud-Instanzen als gemeinsame Datenbank angenommen werden.

Ein `Dockerfile` liegt als Vorbereitung bei. Es wurde nicht mit Docker gebaut oder veröffentlicht. Es setzt standardmäßig den Node-Port 8787 und eine beschreibbare Demo-Datei voraus. Vor Cloud Run den erlaubten Servicehostname explizit konfigurieren; ein auf macOS/ARM gebautes Cloud-Run-Image muss eine unterstützte Linux-Architektur enthalten. Für reine lokale Container-Tests die JSON-Datei über ein passendes beschreibbares Volume erhalten.

Vor jeder tatsächlichen Veröffentlichung erneut prüfen: Transport-/Streaming-Unterstützung, Requestlimits, Cold Starts, Dateiverlust bei Neustart, Zugriffsschutz und aktuelle Tarife. Es gibt hier bewusst keinen automatisch ausgeführten Deploy-Befehl.

Grundlagen: [Cloud Run Containervertrag](https://cloud.google.com/run/docs/container-contract), [Workers Node-Kompatibilität](https://developers.cloudflare.com/workers/runtime-apis/nodejs/), [OpenAI Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).
